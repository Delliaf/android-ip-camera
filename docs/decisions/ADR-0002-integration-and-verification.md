# ADR-0002 — Изоляция веток, интеграция и проверяемые APK

**Статус:** accepted · **Дата:** 2026-11-20

## Контекст

LG H872 функции распределены между PR #1…#5, часть на параллельных ветках и другая в последовательной цепочке. Одна зелёная GitHub Actions сборка не означает, что все изменения из разных веток совместимы, а Camera2 имеет реальные ограничения физической прошивки. Требование пользователя: Android 8 и arm64-v8a, точная история прогресса каждого чата.

## Решение

- База новой работы выбирается по фактическому набору зависимостей — а не автоматически `main`. Проверять текущую ветку и SHA, список PR, target/head, состояние и изменённые файлы.
- Один чат пишет код в **свою** ветку и открывает draft PR, не переписывая ветки других. Статус промежуточной реализации фиксирует в индивидуальном journal main.
- Для каждого значимого коммита разделять уровни проверенности: `planned` → `implemented` → `unit-tested` → `CI/APK-built` → `H872-device-verified` → `ready-to-merge`. Не объединять их в «полностью работает».
- CI run должен относиться к **точному SHA кода**; отдельный документационный коммит может иметь новый HEAD без изменения APK — обозначить это явно.
- Архитектура захвата: пользовательские Camera2 vendor/OEM ключи включать только после проверки capability/ограничений; стандартные API и путь fallback предпочтительнее HAL вмешательства.
- Регрессионная матрица: Camera0/CameraX/Direct Camera2, H.264/RTSP/ONVIF/go2rtc, ISO/shutter/focus, Android8, ARM64 ABI, real FPS/size, thermal, возможный root без небезопасных изменений.
- Мержить stack в правильном порядке после hardware test и review; никогда не сливать черновики автоматически только потому, что компиляция зелёная.

## Последствия

Параллельных PR будет больше, но можно сохранить контекст, проводить независимый review и сравнивать точные результаты. Интегратор обязан разрешать конфликты и определять release-кандидат; обычный чат не объявляет себя интегратором без поручения пользователя.
