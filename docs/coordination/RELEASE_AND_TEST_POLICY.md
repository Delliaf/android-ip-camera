# Сборки и проверки: как не выдавать предположения за готовый APK

## Требования

- Тестовый LG G6 **LG-H872**; Android 8 (API26). Оригинальная конфигурация может поддерживать более старые Android, но цель форка — гарантировать H872 экспериментально.
- **APK и все JNI Rust/OpenTunnel — только arm64-v8a.** В последней экспериментальной ветке `app/build.gradle` делит release по ABI; для debug GitHub Actions отдельно проверяет содержимое `lib/`.
- GitHub Actions для экспериментальных веток: `.github/workflows/android8-fork-ci.yml`. Результат `android-ip-camera-android8-debug` в Artifacts успешного run. Для оригинального `main` используется своя `reproducible-build.yml` — не путать с новой веткой.
- Не передавай пользователю APK от другого SHA под видом новой сборки.

## Порядок верификации изменений

1. До коммита: статическая проверка мест вызова, lifecycle, Camera2 capabilities, потокобезопасности и запросов; для JS `node --check`; для Kotlin/JUnit тесты в `app/src/test`.
2. GitHub CI должен пройти **на точном SHA, включающем изменение кода**. Проверь состояние каждого job, причину ошибок и артефакт, не только зелёный значок другого workflow/branch.
3. Проверка содержимого APK: наличие arm64 JNI и **отсутствие** `armeabi-v7a`, `x86`, `x86_64` внутри `lib/`. Не считать имя файла доказательством.
4. Физический H872: реальные размер/FPS/ISO/shutter/focus/NR/EDGE/crop из `CaptureResult`; устойчивость > несколько минут; температура и заряд; перезапуск Camera0, RTSP+ONVIF/go2rtc; правильность YUV/JPEG/H.264. Без телефона это **не подтверждено**.
5. Подпись: debug APK с другим ключом может не обновить установленное приложение поверх; предупреждай о резервной копии данных. Не проси выкладывать пароль/keystore.
6. Разделяй статус `source-implemented`, `unit-tested`, `apk-built`, `device-tested` и `verified-release`; не заменяй статусы одним словом «работает».
7. Все неудачи, workaround, точный SHA, git diff, ссылки на run, условия окружения, проверенные/непроверенные режимы вписывай в собственный **main/docs/sessions** файл и подробный workstream.

## Образец ручной верификации Camera0

- Проверь две схемы захвата: CameraX (ISP/GPU) и Direct Camera2; не мешай одновременно MJPEG, snapshot и дополнительный ImageAnalysis без проверки HAL.
- Исходный 4:3 кадр `4160×3120` (если реально отдан): при 4× ROI ~`1040×780`, при 4,5× ~`924×693`; в 1:1 области меньше. Запрошенное исходное разрешение **не гарантирует** фактическое.
- Для ISP/manual проверяй фактические `SENSOR_SENSITIVITY`, `SENSOR_EXPOSURE_TIME`, `SCALER_CROP_REGION`, `LENS_FOCUS_DISTANCE`, `NOISE_REDUCTION_MODE` и FPS. На H872 ручной Camera2 ISO рекламируется как 50–800, хотя автоэкспозиция может показывать ISO выше 800; не приравнивай это к доказательству ручного ISO3200.
- Для фото/ZSL сравни `TEMPLATE_ZERO_SHUTTER_LAG(5)` и `RECORD(3)` в одинаковых условиях; шаблон не тождественен OEM постпроцессингу.
- Для go2rtc тестируй отдельно HTTP/HTTPS ONVIF, RTSP кодек, авторизацию и совместимость; не открывай небезопасные порты в интернет.
- CPU/SoC температура может отличаться от батареи: в статусе обязателен **источник**; опциональный root включается отдельно пользователем.

## Сборка по запросу пользователя

Если говорят «сделай APK» — **запусти CI или локальную сборку реально**, разбери сбои, проверь artifacts. Не называй исходник установочным APK. Ссылка на GitHub Actions run является точной и проверенной, только если run найден; артефакт существует, только если это подтверждено API. При невозможности завершить честно укажи последнее проверенное состояние.

## Безопасность

Не публикуй телефонные фото из тестовых ZIP, личные IP, токены, пароли и логи с секретами в открытом репозитории. Не приноси proprietary Android/system .so в GitHub. Root/SELinux/драйверное вмешательство — отдельная рискованная задача, только с явным одобрением.
