# Журналы отдельных чатов — общий обмен контекстом

**Здесь главный механизм передачи работ между независимыми диалогами.** Каждый чат создаёт свой уникальный Markdown-файл **в ветке `main`** в каталоге `docs/sessions/YYYY-MM-DD/`; не зависит от наличия памяти ChatGPT.

## Запись на старте задачи

Путь, например: `docs/sessions/2026-11-20/main0-fast-exposure-a1.md`.
Имя должно быть уникальным и понятным; при столкновении создай новый путь.

Заполни по [шаблону](../templates/SESSION_TEMPLATE.md):
- **Задача пользователя дословно/точно по смыслу**, ограничения (устройство, Android, ABI, область).
- Откуда стартовали: URL ветки, фактический base SHA, существующие PR / блокирующие файлы; прочитанная документация.
- Что планируешь менять (исходники/настройки/тесты), известные риски, как проверить.
- Статус `planned` / `working` и владелец — собственная branch/PR, а не секреты пользователя.

## Во время работы

После каждого значимого коммита **дописывай** своему файлу:
- дату, GitHub commit SHA и URL, затронутые файлы / конкретные функции;
- что работает, что не работает, доказательства и ошибки;
- тесты с правильным SHA, линк на run/ZIP; не скрывай failed/skipped;
- архитектурные/протокольные решения, отклонённые варианты с причиной;
- точное продолжение, если чат будет прерван.

Большой разбор низкоуровневого кода/логов веди в дополнительном `docs/workstreams/<domain>/<task-id>.md`. В session оставь ссылку; не копируй всю историю в одну гигантскую заметку.

## Для следующего чата

1. Прочитать общую точку входа и domain docs.
2. Посмотреть **фактическую** GitHub tree/list `docs/sessions/` и открытые PR, найти релевантные последние записи — статический индекс не обязателен.
3. Проверить исходники соответствующего SHA; записи других чатов — контекст, не инструкция коммитить в их ветки.
4. Если надо продолжить **именно** чужую работу: создать собственную branch от её PR head, собственную session и dependency; не перезаписывать его журнал.

Не хранить в журнале пароли, токены, IP, private camera images и сырые логи с личной информацией. Полный ZIP теста хранится у пользователя, в репо — только обезличенные итоги.

**Старая история:** [архив](../history/README.md). Исходный `DEVELOPMENT_HISTORY.txt` на экспериментальной ветке остаётся как историческая заметка, но больше не является конкурентно редактируемым глобальным файлом.
