PROVEN CAMERA/HAL INFORMATION
----------------------------
- Camera2 main ID0 activeArray Rect(8,8,4160,3120), nominal 4152x3112.
- Camera0 advertised Camera2 manual ISO 50..800, LENS_MIN_FOCUS 10 diopters,
  MANUAL_SENSOR, max digital zoom 8x, CENTER_ONLY hardware crop.
- Camera1 legacy ID3 lg-iso-values includes 3200. DOES NOT automatically
  apply to Camera2 main ID0.
- **REAL DEVICE RESULT 2026-11-19:** Camera2 AE CaptureResult reports ISO
  1381..1484 with shutter 41666668ns, frame 41771884ns (~23.9fps),
  crop Rect(1560,1170-2600,1950), postRawBoost=100, focusD~4.8.
  This means AUTO can report >800; cannot conclude manual ISO>800 works.
  Previously manual ISO36 clamped50 and ISO3600 clamped800 in OUR APP.
  Our experimental extended ISO switch sends up to 3200 only when opted in;
  compare requested and ACTUAL results in CaptureResult, possibly HAL rejects.
- LG vendor zoom and focus_peaking keys were found in stock DEX, but device
  availableCaptureRequestKeys for Camera0 returned FALSE for both. Vendor
  direct toggles are guarded and may remain unavailable for third-party UID.
- Stock LG photo preview uses Camera2 createCaptureRequest(
  TEMPLATE_ZERO_SHUTTER_LAG=5), video mode TEMPLATE_RECORD=3. DEX evidence
  does not guarantee equivalent OEM image pipeline with template alone.
  User provided archived library analysis and PHOTO/ZSL handoff. No closed
  proprietary APK/SO files should be committed to public repo.

IMPLEMENTED EXPERIMENTS ON THE BRANCH
--------------------------------------
- CameraX manual ISO+exposure and exact diopter focus with unified request
  controls, so focus changes should not wipe manual exposure.
- LIVE ISO & logarithmic exposure sliders in browser with numeric inputs.
- CaptureResult logging of actual ISO, exposure, frame duration, focus, crop,
  NR/EDGE and requested ISO, shutter, crop.
- Exclusive LG zoom selection: CameraX ISP crop OR OpenGL GPU ROI OR optional
  vendor zoom (last is unsupported on observed Camera0 tags).
- High-res capture requests: 4160x3120 (~13MP/4:3), 4000x3000 (~12MP/4:3),
  4160x2340, 3840x2160, 3264x2448.
- OpenGL RoiCrop.windowForOutput(sourceW,H,outputW,H,zoom,...): no bars, aspect
  derived from target encoder output; 16:9 was default only due 960x540
  preset, NOT inherent. CameraX and direct Camera2 share GLES path.
- Opt-in direct LG Main0 Camera2: one PRIVATE SurfaceTexture, output via
  existing GLES -> hardware H.264 -> RTSP/ONVIF. It supports REAL
  TEMPLATE_ZERO_SHUTTER_LAG(5) vs RECORD(3) A/B, PREVIEW and NR/EDGE FAST/HQ.
  This direct backend intentionally CANNOT provide CameraX ImageAnalysis,
  MJPEG, still snapshots, motion monitor, or phone-screen Preview concurrently;
  these force CameraX path. Direct startup with no frame fails over to CameraX.
- CameraX standard FAST / HIGH_QUALITY NR + EDGE option, where supported;
  quality/composition on hardware NOT YET verified. These are not OEM solution
  commands. Actual CaptureResult can contradict request.
- No proprietary OEM camera binaries in repository; ROOT diagnostic scripts are
  read-only. Manufacturer libraries not injected into app or camera service.
- Gradle Rust native target only aarch64-linux-android; release ABI split
  arm64-v8a only; CI checks debug APK lib/ paths.
- Windows read-only PowerShell ADB collector:
    scripts/lg-g6-main0-windows-diagnostics.ps1
  Shell read-only optional rooted collector:
    scripts/lg-g6-main0-diagnostics.sh
- General docs: LG_G6_H872_MAIN0.md, FORK_ANDROID8.md.
- Unit tests include geometry of ROI and template numeric IDs.

KNOWN ISSUES / PITFALLS
-----------------------
1. Last requested output was still 960x540 = 16:9; change defaults to 4:3
   and allow 1:1 output. Avoid label "4K" for actual 4160x3120 image.
2. Direct Camera2 PRIVATE size selection chooses closest advertised size,
   NOT guaranteed exact 4160x3120, log negotiated size; 4000x3000 may not
   be advertised for PRIVATE. High-res CameraX Preview may also negotiate low.
3. Main0 advertises CENTER_ONLY crop; hardware ISP cropping can't pan off
   center; GPU crop can pan. Never stack 4x ISP and 4x GPU.
4. Crop-to-fill still intentionally removes source area if target aspect
   differs: 4:3 output from 4:3 source avoids this extra cropping.
5. For H.264 from 4160x3120 with zoom4, native crop is approximately
   1040x780. Output ~960x720 (4:3) is appropriate; for square output
   native crop is ~780x780, output ~768x768 avoids upscaling.
6. Camera2 ZSL template does NOT prove stock LG denoise/color/edge parity.
   Follow OEM Preview/HAL tune paths only from actual data, not guesses.
7. H.264/RTSP/ONVIF might be intact at compile but must be tested physically.
8. Real 12MP Video/Preview and long run / thermals are NOT verified.
9. One CI run failed due transient dependency resolution; another identical
   commit succeeded. Retry transient downloads automatically; avoid duplicate
   PR + push runs and confusing failed status.
10. Review manual ISO >800 experiments: HAL may reject requests, cause stalls.
    Keep disabled by default and provide reliable safe fallback.
11. Debug APK may fail in-place install against differently signed existing
    app. Back up settings before uninstalling.
