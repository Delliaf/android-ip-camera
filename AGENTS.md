# Инструкции для любого ИИ-агента и разработчика

**Готовый промпт для любого нового чата:** [docs/coordination/UNIVERSAL_PROMPT.md](docs/coordination/UNIVERSAL_PROMPT.md).\n\n**Это постоянная точка входа.** Репозиторий: https://github.com/Delliaf/android-ip-camera.
Если выполняешь задачу в другом чате, **НЕ полагайся на историю чата**: её может не быть. GitHub — единственный общий источник контекста.

## Обязательная загрузка контекста ПЕРЕД изменениями

1. Прочитай с **ветки `main`**: [docs/coordination/START_HERE.md](docs/coordination/START_HERE.md), [docs/coordination/PARALLEL_WORKFLOW.md](docs/coordination/PARALLEL_WORKFLOW.md), [docs/coordination/BRANCHES_AND_PRS.md](docs/coordination/BRANCHES_AND_PRS.md) и [docs/coordination/RELEASE_AND_TEST_POLICY.md](docs/coordination/RELEASE_AND_TEST_POLICY.md).
2. Получи **АКТУАЛЬНЫЕ** remote default branch, ветки, открытые PR, их base/head, последние коммиты и Actions. Статическая таблица веток — только срез, не истина на текущий момент.
3. Найди подходящую тему в [docs/workstreams/README.md](docs/workstreams/README.md). Прочитай соответствующие документы, [архитектуру](docs/coordination/PROJECT_ARCHITECTURE.md), недавние записи [docs/sessions/](docs/sessions/) и `DEVELOPMENT_HISTORY.txt` **на актуальной экспериментальной ветке**, если он там есть. Для аппаратного исследования следуй оригинальным handoff/логам, не заменяй их догадками.
4. Определи *реальную ветку-основание* с требуемыми функциями. `main` сейчас содержит исходную версию приложения, экспериментальные LG G6 изменения — в нескольких незавершённых PR. **Нельзя начинать новую LG-функцию от main, если она зависит от кода экспериментальных веток.**

## Правила выполнения любой задачи

- Каждый чат — **отдельный исполнитель**: собственная рабочая ветка и PR; не коммить код в `main`, не изменяй чужую ветку/PR и не объединяй draft PR без явного поручения.
- До первого изменения зафиксируй замысел и выбранное основание в **уникальном** файле `docs/sessions/YYYY-MM-DD/<topic>-<task-id>.md` в **main**. Не редактируй чужие файлы. По мере работы пополняй **этот же файл** фактами: какие файлы, коммиты, тесты, ошибки, CI, ограничения, следующее действие. Для большого направления создай собственный подробный `docs/workstreams/<domain>/<task-id>.md` в main.
- Для изменений кода коммить сразу в свою feature/fix ветку; создай draft PR с правильной base. На каждом важном шаге дополняй общий GitHub-журнал, а не только ответ в чате.
- Сверяй **точный SHA** тестируемого кода с SHA в GitHub Actions. Не выдавай CI старого SHA за тестирование нового. Успешная компиляция ≠ проверка на телефоне. Указывай, какие тесты реально выполнены, какие — нет.
- Работаем на **LG G6 LG-H872, Android 8, Camera2 main ID 0**, но общие функции не должны ломаться на других устройствах. Целевые APK/native библиотеки — **arm64-v8a**. Сохраняй RTSP/ONVIF/CameraX и пути отката, где они требуются. Изменения в коде должны опираться на текущие исходники, а не на старые ответы.
- Не публикуй логи с секретами, ключи, пользовательские кадры, IP/учётные данные, закрытые LG APK/SO и проприетарные бинарники. Root только явно разрешённый и безопасно ограниченный, по умолчанию необязательный.
- Не делай вид, что файл/ветка/PR/сборка созданы, если операция не подтверждена GitHub. Если доступа недостаточно, зафиксируй блокер и сообщи об этом пользователю.
- В конце работы обнови журнал **в GitHub**, создай/обнови PR, оставь тестовую матрицу и следующий конкретный шаг. В ответе дай пользователю ссылки на PR, журнал и проверенный artifact/CI (если есть).

**Параллельность:** не пытайся поддерживать один огромный `DEVELOPMENT_HISTORY.txt` как общий одновременно редактируемый файл. Этот файл — исторический архив экспериментальных веток. Новый обмен информацией — **по одному независимому файлу на задачу в `main/docs/sessions` и `main/docs/workstreams`**. Общие оглавления обновляет интегратор. Подробнее: [PARALLEL_WORKFLOW.md](docs/coordination/PARALLEL_WORKFLOW.md).
